## 解包器选择：优先级 + 兜底链

注册表按 `priority` 升序排列，引擎依次尝试所有 `can_handle` 通过的解包器：

```
原生解包器(50)  →  外部 7-Zip(60)  →  安装包/资源包专用(70/90)
```

只有出现**确定性结果**（成功 / 需密码 / 已跳过）才终止；`失败` / `不支持` 会自动降级到下一个解包器。
因此即使原生实现遇到 LZX 压缩的 CAB，也会自动转交外部 7-Zip 完成 —— 装了就能用，
没装则明确报「不支持」而非虚假成功。

## 双入口设计（GUI / CLI）

命令行参数解析与执行逻辑抽在 `unpacker/cli.py`，两个入口共用，避免重复实现：

```
src/main.py            →  GUI 子系统打包，双击开界面；带参数时尝试挂回父控制台当 CLI 用
src/winunpack_cli.py   →  控制台子系统打包，纯 CLI，不引入 PySide6（体积更小）
```

选择 **GUI 子系统**而不是「控制台程序 + 代码隐藏窗口」，是因为控制台窗口由操作系统在
进程启动前创建，跨进程隐藏并不可靠；改用 GUI 子系统后操作系统根本不会创建控制台。

## 界面主题

全局强制浅色：`launch()` 中设置 Fusion 风格 + 显式浅色 `QPalette`，并在 QSS 中单独
声明 `QMenuBar` / `QMenu` 的白底黑字规则。这样即使 Windows 处于深色模式，
菜单栏与下拉菜单也不会变黑。

界面采用**圆角卡片 + 浅色渐变**的视觉语言，并按功能区划分可折叠分组
（`CollapsibleGroup`：任务队列 / 运行日志 / 输出与重名 / 密码与解包行为）。

## 三层落盘 API（大文件流式）

`BaseExtractor` 提供三档落盘助手，按数据来源选择，**大文件一律不要用 `_write_bytes`**：

| 助手 | 适用场景 | 内存占用 |
|---|---|---|
| `_write_bytes(ctx, out, 名, 数据)` | 已在内存中的小块 bytes | O(数据量) |
| `_copy_stream(ctx, out, 名, 文件对象)` | 已打开的流（ZIP/7z/RAR/TAR/GZip…） | O(1 MiB) |
| `_write_slice(ctx, out, 名, src, offset, size)` | 已打开文件的区间（ISO 扇区、mmap 的 CAB） | O(1 MiB) |

三者统一负责：路径穿越防护、按 `ctx.conflict` 处理重名、累加 `ctx.bytes_written`、
以及**写盘中途失败时删除半成品**（避免解密失败的错位文件污染输出目录）。

配套的解析层也一并流式化：

- **CAB** —— `mmap` 映射整卷，并按 CFDATA 块**按需解压**（MSZIP 的每块是独立 deflate 流，
  可单独解压），峰值内存与 cabinet 体积无关；
- **ISO9660** —— 按扇区偏移直接 `seek` 读取，不预读整个镜像；
- **雕刻器** —— 按 4 MiB 分块把候选区间复制到临时切片，头部/尾部探针用于完整性与区间判定，
  不再把最大 512 MiB 的切片整体读进内存。

## 文件名编码回退

国产压缩工具大量使用 GBK/CP936 存放文件名却不写 UTF-8 标志位，标准库会按 CP437 解码，
表现为**中文名乱码**。处理方式是：

1. CP437 是 0x00–0xFF 的完全单字节映射，因此 `name.encode("cp437")` 可**无损还原原始字节**；
2. 按 `utf-8 → gbk → big5 → shift_jis` 依次 strict 解码；
3. **只有当解出的结果含 CJK 字符时才采纳** —— 这样西文 CP437 名（如 `café.txt`）不会被误改成中文；
4. 全部失败则退回原编码。

编码可显式指定（`--encoding gbk` / 界面下拉），此时不再自动回退。
CAB 成员名走同一套逻辑（默认回退编码为 CP1252）。

## 重名处理策略

`ConflictPolicy` 取代了原先的布尔 `overwrite`：

| 策略 | 行为 |
|---|---|
| `rename`（默认） | 保留两者：`f.txt` 已存在则写成 `f_1.txt` |
| `overwrite` | 直接覆盖 |
| `skip` | 已存在则跳过不写，并计入 `skipped` 统计 |
| `newer` | 归档内成员（无时间信息时用源文件时间）更新才覆盖，否则保留两者 |

跳过的文件数会汇总进结果说明与报告，不会静默丢失。7z 因为不支持按成员选择性落盘，
非覆盖策略下会先解到暂存目录再按规则归位（暂存目录用完即删）。

## 内嵌归档雕刻（Carver）

私有资源包常把标准归档拼接在文件中部或尾部。雕刻器按魔数扫描全文件定位候选，并做三重防护：

1. **完整性预校验** —— ZIP 必须在尾部 128 KiB 内存在 EOCD、单流压缩试解首字节，过滤误报签名；
2. **精确区间排除** —— ZIP 每个成员都带 `PK\x03\x04` 局部头，若不做区间排除会把归档**中段**
   误判为独立归档（这正是开发中 `Errno 22` 的根因）；
3. **超长名截断** —— 单个路径分量限制 120 字符，规避文件系统 255 字节上限。

扫描本身保持**全文件覆盖**（按 4 MiB 分块、9 条签名走 `bytes.find` 的 memchr 快速路径）。
曾评估过「大文件稀疏采样」以进一步降低耗时，但大文件的中段同样可能内嵌归档，
采样会漏检，而扫描并非瓶颈（真正的瓶颈是内存尖峰，已由流式切片解决），故未采用。
