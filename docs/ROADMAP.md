## 一、功能扩展

### 1.1 分卷自动归集 ★★★ 中成本
**痛点**：`report` 里已标注「分卷 CAB 可能缺文件」，用户遇到 `.part1.rar / .z01 / .7z.001 / .001` 时需手动逐卷添加，体验割裂。
**方案**：新增「分卷归集器」——按命名规律（`name.partN`、`name.zNN`、`name.NNN`）把同组文件识别为一个**任务单元**，只把首卷交给解包器（7z/RAR 后端原生支持分卷），其余卷标记为「已随主卷处理」，避免重复解包。
**落点**：`unpacker/engine.py` 的入队阶段前置一个 `group_volumes()`。

### 1.2 密码智能推断 ★★★ 中成本
**痛点**：目前只能靠 `-p` / `--pwfile` 手输，而大量资源包的密码就写在**文件名或目录名**里。
**方案**：三层候选池，按代价递增尝试——
1. **文件名启发式**：用正则从未处理前的中文名中抽取候选（`密码`/`pass`/`pwd`/`解压码` 后的字母数字串）；
2. **同级文件关联**：同目录下 `password.txt` / `说明.txt` / `.nfo` 的内容作为候选；
3. **内置弱口令表**：top 1000 常见密码（仅作低优先补充）。
失败仍回落手动密码表。**注意**：不做大规模暴力/掩码爆破，避免 CPU 打满与合规风险。

### 1.3 完整性校验与「仅测试」★☆ 低成本
**方案**：解包后校验 ZIP/7z/RAR 记录的 CRC，输出「损坏成员清单」；新增 `-t/--test` 只校验不落盘（对齐 `7z t` 语义），退出码 `1` 表示有损坏项。

### 1.4 格式转换与重打包 ★☆ 高成本
**方案**：`--to zip|7z` 把 CAB/ISO/自解压包统一转成标准归档；资源包增加**按类型过滤提取**（`--include "*.png"`），对游戏资源包尤其实用。

### 1.5 归档内容预览 ★☆ 中成本
**方案**：列表 + 右侧目录树，双击成员预览文本/图片（图片用 `QImageReader` 直接读流，不落盘）。是「先看再解」的关键体验。

### 1.6 CLI 工程化增强 ★★☆ 低成本
- `--json`：结构化输出（`[{path, kind, status, files, elapsed}]`），便于管道与自动化；
- `--dry-run`：预演，只打印计划写入的路径；
- `--include / --exclude`：glob 过滤；
- `--threads N`：多归档并行（见 5.1）。

### 1.7 Windows 深度集成 ★☆☆ 高成本
「用 WIN 解包工具打开」「解压到此处」「解压到 <文件夹>\」三项右键菜单 + 注册为可选的「打开方式」。做成安装器里的**可选勾选项**，提供一键卸载，不污染系统。

## 二、文件管理（输出与目录）

### 2.1 冲突策略扩展 ★★★ 低成本
**痛点**：现在只有「覆盖 / 跳过」二元选择。
**方案**：增加「保留两者（`name (1).zip`）」「较新者胜」「大小相同则跳过」，并支持**全局默认 + 单任务覆盖**。

### 2.2 写前路径预演 ★★☆ 低成本
批量解包前弹出**待写入清单**（含冲突标记、总体积、目标盘剩余空间），确认后再执行。这是防「解错目录」「覆盖重要文件」最有效的一道闸。

### 2.3 空间预检 ★★☆ 低成本
用归档声明的 uncompressed size 求和，与目标盘可用空间比对，不足时**执行前**告警，而不是解到 90% 才 `Errno 28`。

### 2.4 输出目录模板 ★★☆ 低成本
支持占位符 `{archive}` / `{date}` / `{ext}` / `{index}`，例如 `D:\out\{date}\{archive}\`。对长期批量归档的用户是刚需。

### 2.5 失败清理与回滚 ★★☆ 低成本
失败任务的半成品输出目录可选自动清理（现在会残留），并在日志中给出被清理的路径，避免「半成品混进成品目录」。

### 2.6 探测结果缓存 ★★★ 低成本
以 `(绝对路径, mtime, size)` 为 key 缓存魔数探测与结构解析结果，重复批量时秒过。缓存文件放 `%USERPROFILE%\.winunpack\cache.json`，带版本号与上限淘汰。

### 2.7 改名映射表 ★☆ 低成本
把「非法字符清洗」「超长名截断」「重名加序号」的**原名 → 落盘名**映射单独输出到报告，便于脚本回写引用。

### 2.8 日志落盘与轮转 ★☆☆ 低成本
`%USERPROFILE%\.winunpack\logs\`，按天/按大小轮转，保留 N 份。长任务（数千文件）出问题时可回溯。

## 三、界面美化

### 3.1 状态图标化 + 颜色编码 ★★★ 低成本
表格状态列用矢量图标（✓ 成功 / ⚠ 需密码 / ✕ 失败 / ⏸ 跳过 / 🔒 加密）替代纯文字，统一色板（成功绿、失败红、需密码橙），扫视效率大幅提升。

### 3.2 进度升级：速度 / ETA / 体积 ★★★ 低成本
当前是「总进度 + 当前文件」双层进度条。补充**瞬时速度、剩余时间（ETA）、已解出体积**，长任务时可判断「还要等多久」。

### 3.3 任务详情面板 ★★☆ 中成本
选中行 → 右侧抽屉显示该归档的成员树、每个文件的解出路径、耗时、命中的解包器与是否走了兜底链。对排查「为什么这个包走了 7-Zip」极有价值。

### 3.4 拖拽可视化 ★★☆ 低成本
拖入时整窗高亮遮罩 + 「将解包 N 个文件 / 共 X MB」提示；拖到表格区域与拖到空白区域给出不同反馈。

### 3.5 主题系统 ★☆☆ 中成本
现在为「强制浅色」（为修 Windows 深色模式下菜单变黑）。建议改为**浅色 / 深色 / 跟随系统**三态开关，并把配色令牌化（QSS 变量集中管理），后续改色不再散落各处。

### 3.6 高 DPI 与缩放适配 ★★☆ 低成本
QSS 中的 `px` 固定值在 125%/150%/200% 缩放下会失衡（文字被截断、按钮大小不匹配）。建议关键尺寸改用 `pt`/相对单位，并在 125% / 150% 下各验证一遍。

### 3.7 无障碍与键盘操作 ★☆☆ 低成本
Tab 顺序完整、Enter 触发主操作、Esc 取消任务、焦点可见环；表头支持排序、任务支持搜索过滤与「紧凑/舒适」密度切换。

### 3.8 完成反馈 ★★☆ 低成本
任务结束给出**摘要卡片**（成功 N / 失败 M / 需密码 K / 耗时 T / 「打开输出目录」按钮）；可选 Windows Toast 通知，长任务可离开干别的。

## 四、包体管理（体积与依赖）

### 4.1 GUI 版瘦身 ★★★ 中成本
**现状**：`WinUnpack.exe` 52.4 MB，绝大多数是 PySide6。
**方案**（按性价比排序）：
1. **排除未用模块**：`--exclude-module PySide6.QtNetwork/QtQml/QtQuick/QtWebEngine*` 等，配合 `--collect-submodules` 白名单化；
2. **UPX 压缩**：`--upx-dir` 可再压 30%+，但**会增加杀软误报**，需权衡（建议提供「压缩版/未压缩版」两个产物）；
3. **换轻量框架**：`tkinter/ttk` 或 `pywebview + 本地 HTML` 可把 GUI 版压到 15 MB 以内，代价是界面表现力下降与较大重写。

### 4.2 分拆「核心版 / 全功能版」★★★ 高成本
**方案**：
- **核心版**：仅标准库 + 自研 CAB/ISO，支持 ZIP / TAR / GZip / BZip2 / XZ / LZMA / CAB(NONE,MSZIP) / ISO，预估 **< 15 MB**；
- **全功能版**：加 `py7zr / pycryptodomex / zstandard / rarfile / olefile`，即当前版本。
核心版覆盖 80% 日常场景且体积小、启动快，是很有价值的发布形态。

### 4.3 启动优化（延迟导入）★★★ 低成本
**痛点**：`--onefile` 每次启动都要把 52 MB 解压到临时目录，冷启动慢。
**方案**：
1. **延迟导入重依赖**——GUI 先出窗口，`py7zr / Cryptodome / zstandard` 等只在**首次真正解包**时才 import（`unpacker/extractors/*` 内改为函数内 import），首屏显著变快；
2. 同时提供 `--onedir` 版（启动快、体积透明），供不介意目录形态的用户。

### 4.4 依赖可选化与体积监控 ★★☆ 中成本
纯 Python 依赖可外置到 `plugins/` 同级目录按需加载（需权衡离线可用性）；构建时打印各包体积占比（`pyi-archive_viewer`），防止依赖膨胀无人察觉。

### 4.5 代码签名 ★☆☆ 高成本
加代码签名证书可消除 SmartScreen「未知发布者」警告。纯成本项（证书年费），但正式分发必备。

## 五、底层优化（引擎与稳健性）

### 5.1 批量并发 ★★★ 中成本
**方案**：多归档用线程池并行（IO 密集，`zlib/lzma/zstd` 均释放 GIL，收益真实），同时限制并发度（默认 `min(4, cpu)`）避免磁盘寻道抖动；进度改为原子累加。

### 5.2 流式解包（大文件）★★★★★ 低成本
**痛点**：`BaseExtractor._write_bytes()` 是「读入内存 → 一次性写盘」，单个 >2 GB 成员会 OOM，这是当前**最硬的功能缺口**。
**方案**：改为分块流式（`shutil.copyfileobj` 式 1 MB 缓冲），ZIP/7z/CAB/ISO 统一走流式接口；保留 `_write_bytes` 作为小块兼容路径。

### 5.3 取消响应性 ★★☆ 低成本
现在靠 `ctx.check_cancel()` 轮询，但单个大文件的连续读块期间无法中断。改为**按块检查 + 可中断 writer**，让「取消」在百毫秒级生效。

### 5.4 探测性能 ★★☆ 低成本 —— ❌ 评估后放弃

**原设想**：把全文件扫描改为「头部 + 尾部 + 稀疏采样」，降低超大文件的扫描耗时。

**放弃原因**：大文件的中段同样可能内嵌归档，稀疏采样会**漏检**（这是一次行为回归，不是优化）；
而扫描本身并不是瓶颈——它已按 4 MiB 分块、每条签名走 `bytes.find` 的 memchr 快速路径，
内存恒定。真正的瓶颈是候选切片的**内存尖峰**（原先最大一次读 512 MiB），
已由 5.2 的流式切片解决。**结论：收益不抵回归风险，不采用。**

若将来确有超大文件扫描缓慢的反馈，可先做无损优化：把 9 条签名各扫一遍
改为「先用单字符类正则定位候选首字节，再校验完整签名」，把 9 趟扫描压成 1 趟。

### 5.5 异常分类收敛 ★★☆ 低成本
全文件扫描的 carver 对超大文件（数 GB 资源包）慢。改为「**头部 + 尾部 + 稀疏采样**」三段式，仅在采样命中可疑魔数时才全扫；同时用 `mmap` 减少拷贝。

### 5.5 异常分类收敛 ★★☆ 低成本
把散落的 `try/except` 收敛为异常层级：`PasswordRequired / CorruptArchive / Unsupported / IoError / CancelRequested`，**报告文案与退出码映射集中在一处决定**，避免各解包器各写一套。

### 5.6 类型标注 + 单测 + CI ★★★☆ 中成本
**方案**：核心层补 mypy 标注；pytest 用例覆盖——
- 各格式最小样本 → 解包成功；
- Zip Slip（`../../evil.txt`）→ 被拦截；
- **相对输出目录回归用例**（开发中踩到的框架级 ValueError）；
- 超长名/非法名/保留设备名 → 正确清洗；
- 加密包 + 密码表 → 命中/未命中。

⚠️ 注意：测试样本以**代码内构造**（`zipfile`/`py7zr` 现造）为主，不往仓库塞二进制夹具。

### 5.7 非 UTF-8 文件名回退 ★★★★ 低成本
**痛点**：国产压缩包大量使用 GBK/CP936 存放中文名，而无 UTF-8 flag 的 ZIP 会被按 CP437 解码 → **中文名乱码**。这是用户抱怨最多的一类问题。
**方案**：解码失败时按「CP437 → 尝试 GBK/CP936 → 再试 Big5/Shift-JIS」回退，并提供一个开关（`--encoding gbk`）强制指定。

### 5.8 日志分级与可复现构建 ★☆☆ 低成本
引入 `DEBUG/INFO/WARN/ERROR` 级别（CLI `-v/-q`、GUI 可切），统一走一个 logger；`requirements.txt` 锁定精确版本（可加 hash）保证他人构建一致。
